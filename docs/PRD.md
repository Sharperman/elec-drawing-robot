## 1. 产品目标与价值主张

### 1.1 背景

电气工程师（尤其是风电/新能源领域）日常需要大量手工绘制强电/弱电系统图、平面布置图、接线图等 AutoCAD 图纸。重复性劳动占据了大量时间，出图质量也受个人经验影响较大，难以标准化。

### 1.2 产品目标

| # | 目标 | 衡量指标 |
|---|------|----------|
| G1 | 将常规电气图纸的绘制时间缩短 ≥ 60% | 对比人工绘图工时 |
| G2 | 图纸符合国标/企业规范的合规率 ≥ 95% | 规范校验通过率 |
| G3 | 用户修改意见的迭代响应满意度 ≥ 4.0/5.0 | 用户评分 |

### 1.3 价值主张

> **"描述需求，机器出图；一键对接 AutoCAD，电气图纸自动生成、持续优化。"**

- **对工程师**：从"手工画图"到"指挥机器画图"，聚焦设计判断而非机械操作。
- **对企业**：统一出图规范、沉淀知识库、降低对高级绘图人员的依赖。

## 4. 需求池（P0/P1/P2）

### P0 — 必须有（MVP 范围）

| ID | 需求描述 | 模块 |
|----|----------|------|
| P0-01 | 通过 AutoCAD COM/ActiveX 接口，在已打开的 AutoCAD 图纸中执行插入图元、连线、标注等基础操作 | AutoCAD 接口集成 |
| P0-02 | 内置电气图元符号库（断路器、隔离开关、变压器、母线、接地、避雷器、互感器、开关柜等），映射到 AutoCAD 块定义 | 图元符号库 |
| P0-03 | 文字输入交互界面：用户以自然语言描述绘图需求，系统解析并调用 AutoCAD 接口执行 | 多模态交互 |
| P0-04 | 图片/图纸上传识别：上传电气图纸图片，识别其中的图元符号并返回结构化描述 | 图元识别 |
| P0-05 | 绘图规范配置：支持导入/配置图层、字体、线型、颜色、图框等基础规范，出图时强制应用 | 绘图规范管理 |
| P0-06 | 基础错误提示：当指令无法解析或操作失败时，给出可读的错误说明 | 系统健壮性 |

### P1 — 应该有（第一个完整版本）

| ID | 需求描述 | 模块 |
|----|----------|------|
| P1-01 | 语音输入交互：通过麦克风采集语音，转录为文字后送入指令解析流程 | 多模态交互 |
| P1-02 | 修改意见学习：记录用户的修改反馈（文字或标注），提炼为规则并在后续出图中应用 | 学习反馈机制 |
| P1-03 | 厂家资料解析：导入设备 PDF/图片，提取型号、参数、外形尺寸等，生成设备图元与材料清单 | 资料解析 |
| P1-04 | 多轮对话上下文保持：同一项目内的多次指令保持图纸上下文，支持"刚才画的那个变压器" 等引用 | 交互体验 |
| P1-05 | 规范校验与提示：出图完成后自动比对规范库，高亮不合规处并给出修改建议 | 绘图规范管理 |
| P1-06 | 强电/弱电系统图、平面布置图、接线图的典型图纸模板库 | 图元符号库 |

### P2 — 可以有（后续迭代）

| ID | 需求描述 | 模块 |
|----|----------|------|

| P2-02 | 版本管理：记录每次出图版本，支持回滚与对比 | 工程管理 |
| P2-03 | 多用户协作：多工程师在同一项目下分工出图，规范库共享 | 团队协作 |

### 外部依赖说明

| 组件 | 集成方式 | 说明 |
|------|----------|------|
| **AutoCAD** | COM/ActiveX（pyautocad / win32com） | 要求本地安装 AutoCAD 2018+；通过脚本接口执行图元操作 |
| **大语言模型（LLM）** | API 调用（云端或私有化部署） | 负责自然语言理解、指令生成、多轮对话 |
| **语音引擎** | 本地 SDK 或云端 ASR API | 语音转文字，推荐支持行业术语自定义 |

| **知识库** | 本地向量数据库（如 Chroma/Faiss） | 存储图元定义、规范文档、用户反馈，支持 RAG 检索 |

### 6.2 关键交互流程

**流程 A：文字指令绘图**
1. 用户在输入框输入绘图需求 → 点击发送
2. 系统在对话区回显解析结果（"将执行：插入断路器 × 1，连接母线"）
3. 用户确认 → 系统调用 AutoCAD 接口执行
4. AutoCAD 预览区刷新，对话区提示"操作完成，如需调整请继续描述"

**流程 B：图片上传识别**
1. 用户点击 📎 上传图纸图片
2. 系统返回识别结果列表（图元名称 + 位置 + 置信度）
3. 用户可点击某图元查看详情，或指令"以此为基础继续绘制"

**流程 C：语音输入**
1. 用户按住 🎤 按钮说话
2. 实时语音转文字显示在输入框
3. 松开按钮自动发送，后续与流程 A 相同

### 6.3 规范配置页

- 规范模板列表（国标 GB/T、行业标准、企业自定义）
- 图层映射表（图层名 ↔ 线型/颜色/线宽）
- 图元符号库管理（查看/导入/自定义）
- 用户偏好记录（已学习的修改意见列表，可启用/禁用/删除）

## 7. 待确认问题与假设

### 7.1 待确认问题

| # | 问题 | 影响范围 | 负责人 |
|---|------|----------|--------|
| Q1 | AutoCAD 版本范围：最低支持哪个版本？是否需要兼容 LT 版本（LT 版 COM 接口受限）？ | P0-01 架构设计 | 技术负责人 |
| Q2 | LLM 部署方式：使用云端 API（如 GPT/通义/混元）还是私有化部署？数据是否允许出境？ | 安全合规、成本 | 业务负责人 |
| Q3 | 图元符号库标准：优先遵循 GB/T 4728（电气图形符号）还是客户企业自有图块库？初期图块数量目标？ | P0-02 工作量 | 产品+用户 |
| Q4 | 学习反馈机制的数据归属：用户反馈数据是否在企业私有库内，不同用户是否共享学习成果？ | P1-02 设计 | 业务负责人 |
| Q5 | 图纸安全与保密：用户上传的图纸是否允许发送到云端进行识别处理？ | 图元识别架构 | 安全合规 |
| Q6 | 首期目标图纸类型：是否优先聚焦"风电场 35kV/10kV 系统图"这一单一类型，还是同时覆盖多种图纸？ | MVP 范围 | 产品+用户 |
| Q7 | 运行环境：客户端是 Windows 桌面应用还是 Web 应用（Web 无法直接调用本地 AutoCAD COM 接口）？ | 技术架构 | 技术负责人 |

### 7.2 当前假设

- **A1**：系统以 Windows 桌面应用形式交付，与本地 AutoCAD 同机运行，通过 COM 接口通信。
- **A2**：初期图元符号库以 GB/T 4728 为基础，后续支持导入企业自定义图块。
- **A3**：LLM 采用云端 API，非涉密图纸场景下可上传图片进行识别；涉密场景后续提供私有化选项。
- **A4**：用户反馈学习数据存储在本地，不同用户/项目之间隔离，企业管理员可统一管理。
- **A5**：MVP 阶段优先支持文字输入，语音输入在 P1 阶段交付。

## 8. 非功能性需求（简述）

| 类别 | 要求 |
|------|------|
| 性能 | 常规指令（单图元操作）响应时间 < 5 秒；复杂图纸生成（50+ 图元）< 60 秒 |
| 可靠性 | AutoCAD 接口调用失败时自动重试 3 次，并给出人工介入提示 |
| 安全 | 本地图纸文件不主动上传；云端 API 调用使用 HTTPS，支持 API Key 轮换 |
| 兼容性 | 支持 AutoCAD 2018 及以上版本；Windows 10/11 64 位系统 |
| 可维护性 | 图元符号库、规范库均以配置文件形式管理，支持热更新 |
